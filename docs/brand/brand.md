# 复盘了 · 品牌说明

更新：2026-11-04。产品名改为「复盘了」。状态：V3「白板 + 画架」标志已应用于 iOS 客户端；后端、Bundle ID 与内部工程名未变。

## 一句话

**复盘了**，一个复盘优先的 AI 持仓复盘。每天收盘后，把持仓读成一句看得懂的话。

- 用户可见名称：**复盘了**
- 拉丁描述：**PORTFOLIO REVIEW**
- 品牌标语：**每天，把持仓读清楚。**
- App Store 建议名称：`复盘了 - 持仓复盘与收盘总结`
- 内部工程名 / Target / Scheme / Bundle ID：仍为 `PortfolioAgent` / `com.portfolioagent.ios`

## 初始命名记录（2026-10-25）

以下保留旧名「复盘志」的命名背景；2026-11-04 起当前产品名为「复盘了」。

原来的「Portfolio Agent」是一个品类描述：portfolio + agent，谁都可以用；P/A 两个字母也只是占位，没有承担产品含义。对一个「复盘优先」的产品，名称和标志应该回答三个问题：它每天做什么、它和别的持仓工具差在哪、它能不能被记住。

「复盘志」把这三件事收进三个字：

1. **复盘**是用户已经会说的词，也是产品底部导航的核心入口，不需要重新教育。
2. **志**把一次性的报告变成一份持续的记录：日报、周复盘、投资记忆、历史报告都能留在同一本「志」里。这是产品真正的差异，不是又一个行情页。
3. 三个字、三个音节，好念、好记、好输入；首页名称不会被截断，也不承诺收益，符合合规边界。

同时它和界面的语气一致：白纸、黑线、等宽字、直角、蓝色强调，像一份编辑出版物，而不是又一个红绿闪烁的行情终端。

## 标志

### 概念

一块架在画架上的白板，板面是当天的复盘。

- **白板（surface + frame）**是读的地方：书写面用来写，浅蓝边框把它从「一张卡片」变成「一块板」。收盘后把今天读给你看的那块板，就是「志」。
- **趋势线 + 箭头**是这一段的走势：一条墨线从本周的低点画到高点，箭头是「向上」的那一撇——不承诺收益，只表示方向。
- **两条墨线**是记录下来的两条观察；其中一条被换成 **粉笔蓝的结论横线**——复盘最后留下的那一句。
- **交叉画架腿**说明板是被架起来给人看的：复盘是讲给人听的，不是自己看的仪表盘。板的顶部就是白板上沿，没有夹子——它是一块干净的被架起来的板。

四组也是四个阅读层级：Conclusion ▸ Ink ▸ Hardware ▸ Board。层序即阅读顺序；高光、折射、厚度由系统负责，我们只给形状和颜色，所以缩到 29pt 仍然干净。

一句话：**趋势是过程，蓝线是结论。**

「蓝 = 结论」是这套品牌里唯一没有变过的东西：V1 是一条蓝色合计线，V2 是一个粉笔蓝圈注，V3 把结论放回一条线——一条画在观察之间的蓝色短横线。形态从「合计」到「圈注」再回到「结论线」，但**蓝色只用来标记复盘后留下的那一句**。

### 沿革（V1 → V2 → V3）

| 版本 | 标志 | 一句话 |
| --- | --- | --- |
| V1 | 三条账目行 + 一条更重的蓝色合计线 | 三行是过程，蓝线是结果 |
| V2 | 一块黑板 + 粉笔图表 + 一个被圈出的结论 | 图表是过程，圈注是结果 |
| V3 | 一块架在画架上的白板 + 趋势线与箭头 + 一条蓝色结论线 | 趋势是过程，蓝线是结论 |

V2 的黑板更像「行情终端的暗面板」，也容易和系统里常见的深色图表图标撞脸；V3 换成白板 + 画架：从「一块屏」变成「一块被架起来、讲给人听的板」，动作感更强，也更接近「复盘」这件事本身。

| 组 | 层 | 源文件 | 内容 | Default 色 |

- Board 组里书写面在画框之前渲染，画框只露出 26 单位的边；这样白板有「面」也有「框」。
- 形状只存在于 SVG 白色掩膜里，颜色只存在于 `palette.json` 里；改色不动形状，改形状不动色。
- **不烘焙效果**：没有高光、阴影、模糊、斜切、描边。Liquid Glass 的光照、镜面、透明由 Icon Composer 与系统按外观渲染。
- 最多 4 个可见组；`.icon` 文档由脚本生成，不手改。源文件的完整约定（命名、数组方向、`<text>` 禁令、3% 最小形状等）见 [`docs/brand/icon/README.md`](icon/README.md)，不在这里重复。
- **已知限制**：iOS 26 之前系统会使用压平回退图，白板面与画框会被压成一色、蓝结论线也可能丢掉层次；iOS 26+（含本项目的 iPhone 18 Pro / iOS 27 目标）按分层正确渲染。品牌物料一律用 `icon-renders/` 里的真实渲染，不要用压平回退图。

### 几何

单位 = App 图标画布 **1024 × 1024**（左上原点），与 `docs/brand/icon/layers/*.svg` 完全一致。

**构图（黄金比例）**：图案（白板 + 画架腿）的外接框缩到画布的 **1/φ ≈ 61.8%**（横向 632.9 / 1024；宽 864 > 高 860，所以按宽取 1/φ），四边留白约 **19–20%**（x ±195.6 / y ±197.0），整体居中。图案顶部即白板上沿，不再有夹子。缩放变换是唯一真源：

```
p' = (512,512) + (p − (512,530)) × 0.732485
```

### AI 入口标志 AgentMark

入口读作 **Ask + 标志**：顶栏只放标志，Ask 页页头是「Ask」+ 标志（不再写 “Ask Ai” 字样）。

标志是一幅**单色黑的小风景**，不是字母、也不是机器人：

- **左 = 山**：一座**向右倾斜**的山——峰尖偏右，左坡长而缓、右坡短而陡，底部齐平；
- **右 = 松树**：上小下大两段塔冠 + 一根树干，与山共用同一条地平线（不画线，靠两端齐平暗示）；
- 两者放进一个 24 × 17 的横向框——一幅小风景，而不是两个字母拼出的字标；「Ai」的意思由「Ask」后面的这个标志承担。
- 只用黑色（`#000000`），实心几何，不加第二色、不加渐变、不加描边。
- 顶栏按宽 **42pt** 渲染（高约 30pt）；Ask 页页头用 38pt；点按区域仍 44×44。无障碍标签 `Ask Ai`，标识符 `askAgent`（保持不变）。
- 深色底同形状改白色，不换字形。

`BrandMark` 与图标同一份几何，但不带纸底，只有「白板 + 画架」的剪影。三种画法：

- 放大版：`BrandMark(style: .whiteboard)`；四组结构完整还原，用于锁屏小组件、空状态插画等大尺寸场景。

### 组合

- 浅色组合：Default 色板——纸色底、白板全色、墨线、粉笔蓝结论线，字标黑。用于应用内、白底文档、浅色网站。
- 深色组合：Dark 色板——书写面转暗米、画框转深蓝灰、硬件转浅暖灰、结论线更亮，字标转白。用于深色物料、启动页。
- 标志在深色底上不换成白色板书；如需单色印刷，把白板、硬件合成一色，墨线与结论线保留，或全墨线稿 + 一条蓝线。
- 最小尺寸：App 图标 29pt（从 `.icon` 渲染，没有单独 PNG）；独立标志 16pt；应用内标志 14pt；组合最小宽度约 120pt。
- 净空：标志四周至少留出标志高度的 **25%**，不压字、不加框。

### 用法

可以：

- 在浅色底用 Default 色板、在深色底用 Dark 色板；两者各自完整。
- 在单色印刷里把趋势线与分析线印成负空间，保留一条结论线作为视觉终点。
- 用 `logo-mark.svg` 放大做海报、用 `logo-lockup-*.png` 做页眉；不重画。

不要：

- 在图标层里加高光、投影、发光、模糊、斜切或任何「假玻璃」效果；这些只由系统渲染。
- 为不同外观画两套图形：六个外观之间只允许颜色变化，形状、位置、层序完全一致。
- 在图标里放文字、轴标签或行情数字。
- 靠小于画布 3% 的细节表达信息（29pt 下会糊）。
- 移动白板、画框、画架腿、趋势线、箭头、结论线的相对位置；改横线数量（3 条：2 墨 1 蓝）或把结论线改成圈。
- 把结论线换成涨跌绿/红，或换成 `#0000FF`。
- 把纸色背景烘进标志本身：纸只属于 App 图标的文档层。
- 用低分辨率位图放大，或手改 `PortfolioAgent/AppIcon.icon`。

重新生成（在 `ios/` 目录）：

```sh
swift scripts/render-brand-assets.swift        # 品牌板 / 平面预览 / 标志 / 组合 / SVG
swift scripts/build-app-icon.swift             # docs/brand/icon/ -> PortfolioAgent/AppIcon.icon
swift scripts/build-app-icon.swift --verify    # 校验 palette.json / icon.json / SVG，渲染六外观并编译
swift scripts/build-app-icon.swift --previews  # 生成 docs/brand/assets/icon-renders/
```

`render-brand-assets.swift` 只依赖 macOS 自带的 AppKit/CoreText 和仓库内已附带的 IBM Plex Mono；PingFang SC 使用系统字体。输出为确定性结果，改几何或文案后重跑即可。`app-header.png` / `app-icon-home-ios27.png` 是模拟器截图，不由脚本生成。`build-app-icon.swift` 与 `icon-renders/` 依赖本机 Icon Composer（Xcode 自带）。

## Icon Composer 工作流

源在仓库里，`.icon` 是产物。完整约定见 [`docs/brand/icon/README.md`](icon/README.md)；这里只记口径：

1. 改色只改 `docs/brand/icon/palette.json`，改形状只改 `docs/brand/icon/layers/*.svg`。
2. `swift scripts/build-app-icon.swift` 生成 `PortfolioAgent/AppIcon.icon`（`icon.json` 键排序 + SVG 原样拷贝）。
3. Xcode 把 `.icon` 交给 `actool` 编进 `Assets.car`，`Info.plist` 的 `CFBundleIconName = AppIcon`。
4. `--verify` 校验 schema、资产完整性、六外观渲染非空且 Default ≠ Dark，并按 Xcode 的方式 `actool` 编译；最后在 iPhone 18 Pro 模拟器看主屏图标。
5. 几何若有改动，同步重跑 `swift scripts/render-brand-assets.swift` 并重画品牌板。

## V2 → V3

| | V2（黑板） | V3（白板 + 画架） |
| --- | --- | --- |
| 概念 | 一块黑板 + 粉笔图表 + 一个被圈出的结论 | 一块架在画架上的白板 + 趋势线与箭头 + 一条蓝色结论线 |
| 一句话 | 图表是过程，圈注是结果 | 趋势是过程，蓝线是结论 |
| 结论的形态 | 粉笔蓝圆环 + 节点 | 粉笔蓝短横线（「蓝 = 结论」回到一条线） |
| 画布内容 | 4 根记录柱 + 趋势线 + 节点 | 趋势线 + 箭头 + 3 条横线（2 墨 1 蓝） |
| 结构 | 4 组：Conclusion / Chart / Tray / Board | 4 组：Conclusion / Ink / Hardware / Board（5 层） |
| 色板 | 板 / 笔 / 记录 / 圈 | 纸 / 书写面 / 画框 / 墨 / 硬件 / 结论线 |
| 外观策略 | 深色外观板书提亮 | 深色外观书写面转暗米、画框转深蓝灰、硬件转浅暖灰 |
| 应用内标志 | 板书剪影 + 记录柱 + 趋势 + 圈 | 板 + 画架剪影 + 挖空墨线 + 蓝结论线（14pt 规则不变） |

V2 的黑板更像行情终端；V3 从「一块屏」变成「一块被架起来、讲给人听的板」。没有变的是「蓝 = 结论」：V1 合计线、V2 圈注、V3 结论线，蓝色只用来标记复盘后留下的那一句。
